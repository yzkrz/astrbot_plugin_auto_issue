# astrbot_plugin_kunter_auto_issue

在用户交流群中收集需求 / Bug 反馈，由 AI 多轮追问补全细节，整理成规范的 GitHub Issue，经确认后自动发布到指定仓库。

## 使用方式

```
用户：@机器人 /issue
机器人：📝 已进入 issue 生成模式，接下来的消息都会被记录。…
用户：导出的 Excel 打开是乱码
机器人：请问你使用的是哪个版本？在什么系统上打开的？方便发一张乱码的截图吗？
用户：v2.3.1，Windows 下用 Excel 打开 [图片]
群友B：我也遇到了，WPS 打开是正常的
机器人：📝 Issue 草稿预览
       标题：[Bug] 导出的 CSV 在 Windows Excel 中打开出现中文乱码
       标签：bug
       ...
       回复「确认」发布，「取消」放弃，或直接回复修改意见。
用户：确认
机器人：Issue 已发布：https://github.com/owner/repo/issues/123
```

### 指令

| 指令 | 说明 |
| --- | --- |
| `/issue` | 进入生成模式，从下一条消息开始记录，多轮对话生成 issue。包含多个独立问题时会自动拆分为多个 issue |
| `/issue list` | 列出仓库当前所有 open 的 issue（不含 PR） |
| `/issue <编号>` | 查看 issue 详情及最近 3 条评论 |
| `/issue <编号> <内容>` | 为 issue 添加评论（可附带图片） |

`/反馈` 是 `/issue` 的别名。群聊中需要 @机器人，私聊无需 @。

### 生成模式

- 会话期间整个群共享同一个会话，群内其他人的补充也会被采纳并记录为参与者。
- 一次反馈多个问题时，AI 会拆分为多个草稿，每个草稿只附带与之相关的图片。
- 回复「生成」/「够了」可让 AI 跳过追问直接生成草稿。
- 与项目开发无关的内容（八卦、娱乐、时事、广告、其他产品的问题等）会被拒绝生成 issue；群友之间的闲聊会被静默忽略。被拒绝或忽略的消息不会写进 issue，发送者也不会被记为参与者。判断是否相关时以配置中的「项目背景介绍」为准，建议认真填写。
- 预览阶段直接回复修改意见（例如「把第 2 个和第 3 个合并」），AI 会修改草稿后再次预览。
- 回复「确认」发布全部草稿，「确认 1 3」只发布指定编号，剩余草稿可继续修改或发布。
- 「确认」「取消」只能由发起人、用户白名单中的用户或 AstrBot 管理员操作。
- 会话期间仍可 @机器人 使用 `/issue list`、`/issue <编号>` 等查询指令。
- 超过设置的超时时间无人发言，会话自动结束。

`/issue` 后面跟其他无法识别的内容时，会回复用法说明。

## 配置项

在 AstrBot 管理面板 → 插件 → 本插件 → 配置 中填写：

| 配置 | 说明 |
| --- | --- |
| GitHub 仓库 | `owner/repo` 或完整 URL |
| GitHub Token | 推荐使用 Fine-grained token，只授予目标仓库 **Issues: Read and write** 权限 |
| list 最多显示条数 | `/issue list` 的显示上限，默认 50 |
| 使用的大模型 | 留空使用当前会话模型 |
| AI 提示词 / 项目背景介绍 | 控制追问风格、issue 格式，并让 AI 了解项目 |
| 最大追问轮数 / 会话超时 | 控制会话长度 |
| 必须 @机器人 | 群聊发起时需要 @机器人 |
| 会话中仅处理 @ 消息 | 开启后群内普通闲聊不会被插件接管 |
| AI 自动打标签 / 可用标签 | AI 只会从可用标签中选择，标签需在仓库中存在 |
| 附带提交者信息 | 正文末尾附上平台、群号、发起人、参与者 |
| 附带图片 / 图片发给大模型 | 图片以聊天平台原始 URL 引用（可能会过期）；识图需模型支持 |
| 群白名单 / 用户白名单 | 留空不限制 |

## 注意

- 默认配置下，会话进行期间该群的**所有消息**都会被插件接管（交给 AI 判断是否与 issue 相关，无关闲聊会被忽略），不会触发机器人的普通聊天回复。如果群比较活跃，建议开启「会话中仅处理 @机器人 的消息」。
- 图片目前直接引用聊天平台的 URL，QQ 等平台的图片链接可能在一段时间后失效。
